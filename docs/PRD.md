## 1. 배경

베어링(주)은 부산 소재 SW 스타트업(업력 1년 미만, 4인: 대표·사내이사·개발팀장·디자이너)이다. 정부지원사업에 꾸준히 지원하려는데 지금은 아래가 전부 수작업이다.

- 기업마당, K-Startup, 지자체·진흥원 사이트, 뉴스레터를 사람이 직접 훑는다
- 공고문(PDF/HWP)을 읽고 우리가 자격이 되는지 판단한다
- 링크·공고·마감일을 Slack에 수동으로 공유한다
- 공고마다 사업계획서를 처음부터 쓴다. 이전에 쓴 내용을 재활용하기 어렵다

팀 내부 요청(2026-11-23 Slack): "링크와 사업공고, 데드라인까지만 일괄로 보내게 하자", "뉴스레터를 끌어와서 초안까지 만들어 주자".

## 2. 목표 / 비목표

### 목표
1. 새 공고를 **매일 자동으로** 모은다
2. 우리 회사 정보 기준으로 **맞는 공고만 점수순으로** 보여준다. 왜 맞는지/안 맞는지 근거를 함께 보여준다
3. 진행할 공고는 **첨부 양식 다운로드 + 사업계획서 초안 자동 생성**까지 한 번에
4. 사람이 리뷰하고 완성하는 **진행 상태(파이프라인)를 팀이 함께 본다**
5. 지원할수록 **회사 메모리(이전 계획서, 지원 이력, 결과)가 쌓여 초안 품질이 좋아진다**

### 비목표 (지금은 안 함)
- 외부 판매, 결제, 멀티테넌시(회사 1개 고정. 단, 스키마는 `company_id`를 두어 나중 확장 여지만 남긴다)
- 지원 시스템(K-Startup 등)에 **자동 제출**. 제출은 사람이 직접 한다
- 모바일 앱. 반응형 웹이면 충분하다

### 성공 기준 (내부)
- 주간 공고 확인에 쓰는 시간이 체감상 크게 줄어든다(팀 회고로 판단)
- 지원 결정한 공고의 사업계획서 초안이 **30분 안에** 리뷰 가능한 상태로 나온다
- 마감을 놓치는 공고가 없다

- 추천·초안은 이미 경쟁이 많다: 파트너잇(공고 AI 구조화+적합도), 위커밋(젠닥: 선별+원클릭 초안), 모두플랜·The Grant·메이크덱(계획서 작성), ZUZU(계획서 피드백) 등

## 5. 핵심 흐름 (5단계)

```
① 소싱 ──▶ ② 회사 정보 ──▶ ③ 매칭·점수 ──▶ ④ 문서 다운로드 + 초안 ──▶ ⑤ 리뷰·완성 ──▶ 제출(사람)
   매일 자동     프로필·메모리     하드필터+LLM        양식 파싱, 섹션별 초안        코멘트, 버전, 상태
```

### 상태(파이프라인) 정의 — 디자인의 상태 칩과 1:1

| 상태 키 | 화면 표기 | 의미 | 칩 색 |
|---|---|---|---|
| `new` | 새 공고 | 매칭됨, 아직 아무도 안 봄 | blue |
| `triage` | 검토 전 | 열람했지만 진행 결정 안 함 | gray |
| `interested` | 관심 | 1차 분류에서 관심 표시 (상세 화면 아래 분류 바). 관심 없음은 `excluded`(사유 칩) | yellow |
| `drafting` | 초안 작성 중 | 진행 결정, 초안 생성/편집 중 | purple |
| `review` | 리뷰 중 | 리뷰어 지정됨 | orange |
| `submitted` | 제출 완료 | 사람이 실제 제출함(제출일 기록) | green |
| `result_pass` / `result_fail` | 선정 / 미선정 | 결과 기록 → 회사 메모리에 반영 | green / gray |
| `excluded` | 제외 | 하드필터 탈락 또는 사람이 제외(사유 필수) | gray, 흐리게 |

## 6. 기능 요구사항

### ① 소싱
- F1.1 기업마당 API, K-Startup(공공데이터포털) API에서 매일 1회 이상 신규·변경 공고 수집
- F1.2 수동 추가: 공고 URL 붙여넣기 → 페이지 파싱 → 공고 생성 (지자체·진흥원 단독 공고, 뉴스레터에서 본 공고)
- F1.3 중복 제거: 같은 공고가 두 소스에 있을 때 하나로 합친다(제목 정규화 + 기관 + 마감일 기준)
- F1.4 공고 원문·첨부파일 메타데이터 저장. 첨부파일 실제 다운로드는 ④에서 진행 결정 시
- F1.4.1 뉴스레터 붙여 넣기 (2026-11-26): 피트페이퍼 공유 링크 → 안의 지원사업·행사·뉴스·투자 줄을 전부 공고로 (센서블박스 위클리로 확인)
- F1.5 (이후) 뉴스레터 메일 수집: 팀 메일함의 특정 라벨 → 링크 추출 → F1.2와 같은 경로. *Eddie가 말한 뉴스레터 이름 확인 필요*

### ② 회사 정보 (회사 메모리)
- F2.1 회사 프로필: 법인명, 설립일(→업력 자동 계산), 소재지, 업종(KSIC), 기업 유형(법인/개인, 벤처 인증 여부 등), 인원, 매출 구간, 대표자 연령대(청년 요건용), 보유 인증·특허, 주력 아이템 설명
- F2.2 아이템 카드: 제품별(예: ONDECKK) 문제·해결·고객·차별점·성과 지표. 초안 생성의 핵심 재료
- F2.3 문서 라이브러리: 사업자등록증, 이전 사업계획서, IR 자료 등 업로드 → 텍스트 추출 → 초안 생성 시 검색(RAG)해서 사용
- F2.4 지원 이력: 공고별 상태, 제출본, 결과, 심사 피드백. 결과가 쌓이면 매칭·초안 프롬프트에 반영
- F2.5 제외 규칙: "이런 공고는 보지 않기"(예: 제조 전용, 수도권 한정) 키워드·조건

### ③ 매칭·점수
- F3.1 1단계 하드필터(규칙): 마감 지남, 업력 범위, 지역 제한, 대상(예비창업자 전용 등), 제외 규칙 → 탈락 시 `excluded` + 사유 자동 기록
- F3.2 2단계 LLM 점수: 0~100 점수, 맞는 이유 3개 이내, 리스크·확인 필요 항목, 추천 아이템 카드. JSON 스키마로 받는다
- F3.3 정렬: 점수 + 마감 임박 가중치. 홈 "이번 주에 챙길 공고" = 7일 이내 마감 또는 점수 85+ 중 진행 상태가 `new`/`drafting`/`review`
- F3.4 사람의 판단 기록: 진행/제외 클릭과 제외 사유를 저장 → 이후 점수 보정 근거

### ④ 문서 다운로드 + 초안
- F4.1 진행 결정 시 첨부파일(공고문, 신청서·사업계획서 양식) 다운로드·저장
- F4.2 양식 파싱: HWP/HWPX/DOCX/PDF에서 섹션 구조(목차, 작성 요령, 분량 제한) 추출. 실패 시 공고 유형별 기본 템플릿(창업패키지형, 바우처형, R&D형)으로 대체
- F4.3 섹션별 초안 생성: 회사 프로필 + 아이템 카드 + 문서 라이브러리 검색 결과 + 공고 평가 기준을 넣어 섹션 단위로 생성. 분량 제한 준수
- F4.4 근거 없는 내용 금지: 프로필에 없는 수치·실적은 `【확인 필요: …】`로 남긴다. 화면에서 노란 하이라이트로 표시
- F4.5 제출 서류 체크리스트: 공고에서 요구 서류 추출 → 문서 라이브러리와 매칭(준비됨/미첨부)
- F4.6 (M4 이후) 원본 양식에 채워서 내보내기: DOCX 우선, HWPX 다음, HWP(구형)는 변환 경유

### ⑤ 리뷰·완성
- F5.1 섹션별 에디터, 섹션 단위 재생성("더 구체적으로", "분량 줄이기")
- F5.2 리뷰어 지정, 섹션에 코멘트, 해결 처리
- F5.3 버전 기록(초안 생성본 / 수정본 비교)
- F5.4 내보내기: DOCX, PDF, Markdown
- F5.5 제출 완료 기록(제출일, 제출본 파일 첨부), 결과 기록

### 공통: 알림

- F6.2 마감 D-7, D-3, D-1 알림 (진행 중 공고만)
