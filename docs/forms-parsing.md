# 양식 파싱 측정 (M4)

M4 첫 작업: 실제 공고 첨부 양식으로 Node만으로 글자를 뽑을 수 있는지 재고, Python `doc-worker`를 둘지 정한다.

## 샘플
2026-11-23 기업마당·K-Startup에서 진행 중 공고의 신청 양식 12개를 받았다 (목록 `fixtures/forms/manifest.tsv`, 파일 자체는 커밋 안 함).
형식 분포: HWPX 7, HWP(5.x 바이너리) 3, DOCX 1, PDF 1.

## 결정: doc-worker 두지 않는다
- 구현: `src/server/docs/` — HWPX·DOCX는 zip(fflate) + XML(fast-xml-parser), HWP 5는 OLE(cfb) + 본문 레코드(raw deflate) 직접 읽기, PDF는 unpdf
- HWP 5는 한컴 공개 명세 "한글 문서 파일 형식 5.0"의 레코드 구조(PARA_TEXT 67, CTRL_HEADER 71, LIST_HEADER 72, TABLE 77)만 쓴다. 표 셀은 LIST_HEADER의 열·행 주소로 다시 배치
- 못 읽는 경우는 이유를 남긴다: 배포용 HWP(본문 암호화), 암호 문서, 스캔 PDF(글자 없음), xlsx·zip·이미지
- unpdf는 0.12.1로 고정: 2.x에 든 pdf.js가 Node 22의 `Iterator`를 써서 이 Mac(Node 20)에서 안 돈다
- 다시 검토할 때: 배포용 HWP가 자주 나오거나, 원본 양식에 채워 내보내기(F4.6)를 할 때 (HWP 쓰기는 Node로 어렵다)

## 섹션 추출
글자는 규칙 없이 뽑고, "어느 부분이 써야 할 섹션인가"는 LLM이 정한다 (`src/server/prompts/form-sections.v1.ts`).
양식마다 번호 체계·표 배치가 제각각이라 규칙 기반 섹션 파싱은 하지 않았다. LLM이 없거나 섹션을 못 찾으면 기본 템플릿(창업패키지형/바우처형/R&D형).
